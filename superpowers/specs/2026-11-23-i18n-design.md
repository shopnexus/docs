# Languages for the app, the website and the server

Date: 2026-11-23. Status: phase 1 done on 2026-11-23 (Vietnamese on the
structure English needs, wording to `docs/manual/thuat-ngu.md`, checks in
`make i18n`); phase 2 adds English. How to work with it:
`docs/i18n/README.md`.

## The two kinds of text

| | Client text | Server text |
|---|---|---|
| What | Everything the app or the site draws: screens, labels of codes, errors by code, formatting | Text the server composes from its own state or owns as data |
| Examples | buttons, titles, order status names, "3 giờ trước", "3,8 tr" | notices and pushes, mail, search chips, category names, scam signal sentences |
| Lives in | Android `res/values*/strings.xml`; website `src/i18n/<tag>.ts` | `<package>/text/<tag>.json` catalogs through `platform/locale` |
| Language picked by | the client's own setting | the request's `Accept-Language`; pushes and mail use `accounts.locale` |

User content (titles, descriptions, chat, reviews, names, places) is never
translated. Model output follows the language it is asked for: listing
drafts stay in the marketplace's language (Vietnamese).

## One locale per person, decided by the client

- The client decides the language and says it on every request as
  `Accept-Language`. The server never guesses from IP or account.
- App: the per-app language (Android 13+ `LocaleManager`, declared in
  `locales_config.xml`); default is the device's when it is a supported
  language, else Vietnamese. `Accept-Language` is read per request from
  the app's locale.
- Website: the URL decides. Vietnamese has no prefix (`/search`);
  English will live under `/en` (`/en/search`), with `hreflang`
  alternates and per-language sitemaps. The middleware sets
  `Astro.locals.lang` from the path and forwards that language, not the
  browser's header, to the API. A first visit to `/` with an English
  browser gets a small "View in English" link, never a redirect
  (crawlers and shared links stay stable).
- Server: `locale.FromRequest(r)` for response text; sign-in records it
  as `accounts.locale` for pushes and mail.

## API rule: codes first

The server sends codes and parameters whenever a client can write the
sentence, and text only when the text is data it owns or composes from
state a client does not have.

Phase 1 server changes (no new text, only codes beside it):

- `ScamSignal` gains `params` (days, percent); clients write the sentence
  from `code` + `params`, `text` stays for older clients.
- Photo refusals gain `failure_code` (`too_large`, `wrong_type`,
  `unreadable`, `too_many_pixels`).
- Error `fields` gain codes (`too_long`, `out_of_range`, `missing_specs`)
  beside the English developer text.
- `SearchItem` and saved listings gain `commune_code` beside the name.

Server-localized in phase 2, when English exists:

- Category names: a `category_names(code, locale, name)` table, picked by
  `Accept-Language` in `/v1/categories` and Home; embeddings, prompts and
  search history keep the Vietnamese name. Responses that vary send
  `Vary: Accept-Language`, and the website caches per language.
- Spec labels need stable keys first (`spec_labels: [{key, name}]`,
  listing specs `{key, label, value}`), so a translated label cannot break
  posting or `missingSpecs`. This is its own change.
- Search chips move into `discovery/domain/text/<tag>.json`.
- Regions stay Vietnamese proper nouns.

## Formatting, the same on three platforms

One table of cases, `docs/i18n/format-cases.json`, that the server, the
app and the website each test against, so "3,8 tr" reads the same
everywhere:

| Case | vi | en |
|---|---|---|
| money full | 3.800.000 ₫ | 3,800,000 ₫ |
| money short | 3,8 tr | 3.8M ₫ |
| decimal (rating) | 4,8 | 4.8 |
| day and month | 30/11 | Nov 30 |
| time | 14:05 | 14:05 |
| relative | 3 giờ trước | 3 hours ago |
| count + noun | 2 ảnh | 2 photos / 1 photo |

Each platform has one formatting module and nothing else formats money,
dates or counts: server `platform/locale`, app `core:model` `Formats`,
website `src/i18n/format.ts` (built on `Intl`).

## Client structure

### App (Kotlin, Compose)

- Strings already live in resources (1,462). Phase 1:
  - `locales_config.xml` with `vi` (and `en` in phase 2),
    `android:localeConfig`, `generateLocaleConfig`.
  - `Formats` in `core:model`: money, short money, decimal, dates and
    relative time from a `Locale`, replacing `MoneyFormat`, the five
    rating helpers and `Labels.kt`'s day words.
  - Domain and data stop returning sentences: `ThreadItem.Event`,
    inbox previews, `Deal.cancelled(line)` and the `Labels.kt` helpers
    return typed labels (sealed classes with arguments, like
    `DraftLabel`) that `core:ui` writes with `stringResource`.
  - Count strings become `<plurals>`; lint's `PluralsCandidate` comes
    back on.
  - Tests read text from resources (`context.getString`) where they
    assert copy; Robolectric runs pin `vi`.
- Phase 2: `values-en/strings.xml`, a "Ngôn ngữ" row in Cài đặt.

### Website (Astro SSR)

- `src/i18n/vi.ts` is the source dictionary: a nested object of
  functions and strings, grouped by page or component. `en.ts` is typed
  `Dict` (`typeof vi`), so TypeScript fails the build on a missing key.
- `Astro.locals.t` (set by the middleware from the path) is the only
  way pages and components read copy: `t.orders.status.shipped`,
  `t.listing.photos(n)`. Plurals go through `Intl.PluralRules`.
- Browser scripts get a small client dictionary: `Layout` writes
  `<script type="application/json" id="words">` with only the keys
  browser code uses (`src/i18n/client.ts` names them), so bundles carry
  no dictionary.
- Text used as a key goes: `LINK` keyed by route, `GRADE` keyed by
  condition code, `when()` compares dates, not labels.
- `<html lang>`, `og:locale`, JSON-LD `inLanguage`, the manifest and the
  service worker's notification `lang` read the locale.
- `R` stays the only way to build a path; phase 2 makes it
  locale-aware (`routes(lang)`), and the hand-written path checks
  (speculation rules, quick view, chat dock, robots) go through it.
- `src/data` editorial content (FAQ, terms, flows) moves to
  `src/i18n/content/<tag>/*.ts`; the `MONEY` sentences stay word for word
  with the app's resources.

## Phases

1. Vietnamese on the structure (this change):
   - format cases file; server codes beside text (list above);
   - app: locale config, `Formats`, typed labels out of domain/data,
     plurals;
   - website: `src/i18n`, middleware `lang`, `t` through every page and
     component, client words, `lang`-driven `html`/meta.
2. English: `values-en`, `src/i18n/en.ts`, `/en` routes and SEO
   alternates, server catalogs for categories, chips and spec labels,
   the language row.

## Out of scope

Right-to-left scripts, currency other than đồng, translating user
content, machine translation of listings.
