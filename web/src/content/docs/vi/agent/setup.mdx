Server là nơi duy nhất giữ cấu hình của một agent. Agent không giữ bản sao nào: mỗi đoạn chạy nhận cấu hình trong các trường `agent_config` và `gateway` của `POST /runs`.

## Agent trong `ai_agents`

Bảng `ai_agents` của server chứa hai loại agent, và các dòng đầu tiên được tạo sẵn.

| Loại | Agent tạo sẵn | Ai dùng | Quản trị viên làm được |
|---|---|---|---|
| `console` | Console assistant (`console-agent`) | điều phối viên, chọn trong ô hỏi | tạo, sửa, bật và tắt |
| `app` | Scam check, Listing photo reader, Search, Search embeddings | code của server | đổi model, giới hạn và ngân sách |

Một agent có tên hiển thị ("Console assistant") và một slug (`console-agent`), cũng là tên team của nó trong Bifrost. Mỗi lần lưu hướng dẫn mới, server thêm một phiên bản vào `ai_agent_versions` kèm người lưu và thời điểm. Câu hỏi không chọn agent nào thì dùng Console assistant. Agent không tồn tại hay agent loại `app` thì trả 404 `ai_agent_not_found`, agent đã tắt thì trả 409 `ai_agent_disabled`.

Quản trị viên quản lý agent trong **Settings** của trang điều hành; [Cài đặt AI](/vi/architecture/ai) mô tả phía server. Trang của một agent giữ model (nhà cung cấp và model), các model dự phòng, ngân sách tháng và giới hạn tốc độ của các bên gọi; mỗi model có một giá. Trang Providers chỉ để xem, vì thêm nhà cung cấp là một thay đổi về infra. Server ghi team, virtual key, ngân sách và giá vào Bifrost qua admin API của nó ([Cổng Bifrost](/vi/operations/cluster/llm-gateway#key-và-ngân-sách)).

## Cấu hình theo đoạn chạy

```jsonc
"agent_config": {
  "id": "uuid", "name": "Console assistant",
  "instructions": "…", "instructions_version": 3,
  "tools": ["ticket_get", "account_get"],  // tool MCP agent được dùng
  "limits": { "deadline_s": 60, "max_model_calls": 40, "context_window": 128000,
              "tool_timeout_s": 20, "tool_attempts": 3, "max_tokens": 4096 }
},
"gateway": {
  "key": "sk-bf-…",                         // virtual key của agent trong Bifrost
  "model": "upstream/claude-sonnet-5-5",   // provider/model
  "fallbacks": [],                         // provider/model, thử lần lượt
  "prices": { "upstream/claude-sonnet-5-5": { "input": 2e-6, "output": 1e-5, "cache_read": null, "cache_write": null } }
}
```

Agent bỏ các khóa lạ của `agent_config`. Một giá trị ngoài khoảng cho phép làm cả request bị từ chối với 400. Đoạn chạy thiếu `gateway` cũng bị từ chối với 400. Agent không bao giờ ghi log hay lưu key, và tính giá mỗi lần gọi theo `prices` (USD cho mỗi token; giá cache để null thì bằng giá input).

System prompt của một đoạn gồm prompt có sẵn (vai trò, bản ghi đang mở, quy tắc điều phối và hỗ trợ), quy tắc của output tool, `instructions` của agent và prompt của skill khi câu hỏi dùng skill.

## Biến môi trường

Các giá trị giống nhau ở compose và mọi stack của cụm nằm trong một file môi trường chung của agent, và cả hai đều đọc file đó. Hai token được sinh cùng các key khác của stack. Agent không giữ key model nào của riêng nó.

| Biến | Phía | Ý nghĩa |
|---|---|---|
| `AGENT_BASE_URL` | server | Địa chỉ nội bộ của agent, như `http://agent-dev:3000` |
| `AGENT_SERVICE_TOKEN` | cả hai | Token server gửi kèm `POST /runs`; để rỗng thì mọi request bị từ chối |
| `AGENT_MCP_ADDR` | server | Địa chỉ lắng nghe của MCP server, `0.0.0.0:9090` |
| `AGENT_MCP_TOKEN` | cả hai | Token agent gửi tới MCP và endpoint điều khiển |
| `MCP_SERVER_URL` | agent | `/mcp` của server, như `http://server-dev:9090/mcp`; origin của nó cũng phục vụ endpoint điều khiển |
| `GATEWAY_BASE_URL` | agent | Endpoint tương thích OpenAI của Bifrost, `http://bifrost:8080/v1` |
| URL admin và thông tin đăng nhập của Bifrost | server | Để ghi team, key và ngân sách, và cho các trang Settings |
| `AGENT_TURN_DEADLINE_MS` | agent | Thời hạn mặc định của một đoạn, 60 000 |
| `FEATURE_ALL_AGENT`, `FEATURE_LLM` | agent | `false` thì mọi đoạn chạy bị từ chối với 503 |

Mỗi token dài ít nhất 32 ký tự; bộ sinh môi trường của server ghi cả hai thành 32 byte ngẫu nhiên. Không dòng log nào chứa token, key của gateway hay mật khẩu admin. File môi trường mẫu trong repo agent liệt kê các biến còn lại, tất cả đều không bắt buộc.

## Chạy thử ở máy

Agent không có file compose riêng. Nó chạy trên Bifrost và MCP của stack, từ `docker-compose.yml` của repo umbrella hoặc từ cụm.

```bash
cd agent
npm install
cp .env.example .env
# Điền AGENT_SERVICE_TOKEN, AGENT_MCP_TOKEN, MCP_SERVER_URL, GATEWAY_BASE_URL và CLI_GATEWAY_KEY theo stack.
npm run start:dev
npm run chat -- "Có bao nhiêu ticket đang mở?"
```

`npm run chat` gửi một đoạn `new` tới agent trên `PORT` với tư cách `CLI_MEMBER_ID`, kèm `CLI_GATEWAY_KEY` và `CLI_GATEWAY_MODEL` làm `gateway` với giá bằng 0, rồi in các event và dòng `end`. Lấy key từ team `console-agent` trong giao diện của Bifrost. Lệnh này gọi model và MCP thật, nên có thể tốn tiền. Không có endpoint điều khiển của server thì các lần hỏi lệnh điều khiển đều lỗi, và đoạn chạy tiếp mà không có Pause, Stop now hay cập nhật.

## Kiểm tra

```bash
npm run build
npm run typecheck
npm test                  # chạy offline, với một model có kịch bản và một server giả
npm run test:live-cache   # gọi Bifrost thật; bỏ qua khi chưa đặt gateway thật
```
