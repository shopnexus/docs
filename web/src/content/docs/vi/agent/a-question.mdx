Một câu hỏi là một lượt (turn). Một lượt chạy thành một hay nhiều đoạn (segment): mỗi lần tạm dừng rồi chạy tiếp, hay hỏi lại moderator rồi chạy tiếp, server mở một đoạn mới trên agent, nối từ checkpoint của đoạn trước. Agent không có database; checkpoint nằm ở server, trong cột `state` của lượt.

## Các bước

<Steps>
<Step title="Server nhận câu hỏi">
Server kiểm phiên console, đọc agent được chọn trong `ai_agents` (mặc định là Console assistant), kiểm ngân sách tháng, giới hạn 30 câu hỏi và cập nhật mỗi phút cho mỗi moderator, rồi làm sạch câu hỏi: bỏ ký tự điều khiển, ký tự độ rộng 0 và thẻ HTML. Câu hỏi quá 2000 ký tự bị từ chối với `agent_input_rejected`. Lượt mở ở trạng thái `running` dưới khoá dòng của cuộc chat, và console nhận `202 {conversation_id, turn_id}`.
</Step>

<Step title="Server mở một đoạn chạy">
Server gửi `POST /runs` tới agent với `AGENT_SERVICE_TOKEN`: câu hỏi, moderator và vai trò, bản ghi đang mở, 20 lượt đã xong gần nhất làm lịch sử, `agent_config` (hướng dẫn, danh sách tool, giới hạn) và `gateway` (virtual key, model, model dự phòng và giá). Server chờ agent trả trạng thái tối đa 10 giây; khác 200 thì lượt mới bị bỏ và console nhận `503 agent_unavailable`.
</Step>

<Step title="Agent mở MCP và chạy vòng lặp">
Agent mở một client MCP mới cho đoạn chạy và chỉ giữ tool có `readOnlyHint` nằm trong danh sách của agent. Model mở bước bằng `begin_step`, gọi tool, đóng bước bằng `end_step` với một dòng tóm tắt, và trả lời bằng `answer`. Trước mỗi lần gọi model, agent ghi checkpoint và đọc các lệnh điều khiển đang chờ.
</Step>

<Step title="Từng dòng chảy về server">
Agent ghi mỗi việc thành một dòng JSON và flush ngay. Server đọc stream ở chế độ nền: dòng `event` được lưu với số thứ tự kế tiếp rồi báo cho các stream đang mở qua `pg_notify`; `checkpoint` lưu trạng thái để chạy tiếp; `tool_call` cập nhật dòng của lần gọi tool; `document` lưu phiên bản mới của tài liệu.
</Step>

<Step title="Console vẽ lượt chạy">
Console mở `GET /v1/console/agent/turns/{id}/events`. Server phát lại các event đã lưu rồi gửi tiếp event mới, mỗi event có `id` là số thứ tự. Mở lại trang thì console xin từ số thứ tự cuối nó đã thấy, qua `Last-Event-ID`. Khi moderator đóng tab, server đóng stream và lượt vẫn chạy trên agent.
</Step>

<Step title="Dòng end khép đoạn">
Dòng cuối mang trạng thái, câu trả lời, các khối, nguồn, chi phí, checkpoint và event đóng. Server ghi tất cả trong một transaction. Stream đứt mà không có dòng `end` thì lượt đóng `failed` với `agent_stuck`.
</Step>
</Steps>

## Cách một đoạn kết thúc

  items={[

  ]}
/>

`PAUSED` và `AWAITING_INPUT` chưa khép lượt: moderator chạy tiếp, trả lời hoặc kết thúc. Lượt `FAILED` hay `TIMED_OUT` chạy tiếp được trong một số trường hợp, liệt kê ở [Giới hạn và lỗi](/vi/agent/limits).

## Server dọn lượt bị treo

Mỗi replica của server giữ một `LISTEN agent_turn` để báo các stream của lượt. Lúc khởi động và mỗi phút, server đóng các lượt còn `running` quá 30 giây sau thời hạn với `agent_stuck`, kể cả lượt của một replica đã sập giữa chừng.
