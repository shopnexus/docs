Người dùng đăng nhập bằng số điện thoại, tài khoản Google hoặc mã OTP gửi qua email. Lần đăng nhập đầu tiên sẽ tạo tài khoản. Nhân viên thì đăng nhập bằng cookie phiên; xem [Trang điều hành](/vi/architecture/console).

## Đăng nhập

Gửi một bằng chứng lên `POST /v1/auth/sign-in`, kèm `Idempotency-Key` và tên thiết bị (không bắt buộc):

```json title="POST /v1/auth/sign-in"
{ "phone_token": "eyJhbGciOi...", "device_name": "Pixel 9" }
```

- `phone_token`: token Firebase trả về sau khi xác minh bằng mã SMS hoặc bằng SIM. Có token rồi thì đăng xuất khỏi Firebase.
- `google_token`: ID token lấy từ Android Credential Manager.
- `email_code`: `{challenge_id, code}`. Lấy challenge trước bằng `POST /v1/auth/email-codes {"email": "…"}`.

Kết quả gồm `access_token`, `access_token_expires_at`, `refresh_token` và `account`. `account.is_new` nghĩa là lần đăng nhập này vừa tạo tài khoản, nên hỏi thông tin hồ sơ.

| Kết quả | Cần làm gì |
|---|---|
| 401 `invalid_phone_token`, `invalid_google_token` | lấy token mới (token sống 5 phút) |
| 422 `invalid_phone` | số không phải số di động Việt Nam |
| 422 `invalid_code` | cho người dùng nhập lại; xem `details.attempts_left` |
| 422 `code_expired`, `code_locked` | xin mã OTP mới |
| 429 `otp_too_soon`, `otp_limit` | chờ `details.retry_after` giây |
| 503 `unavailable` | gửi lại với chính token đó |

## Gọi API

```http
Authorization: Bearer <access_token>
```

Access token sống 15 phút. Trên lời gọi dùng bearer, 401 luôn nói về bearer (`unauthenticated`, `invalid_token`, `session_revoked`, `session_expired`); bằng chứng sai trên lời gọi như vậy trả 422. 403 `phone_required` nghĩa là lời gọi cần số điện thoại; thêm số bằng `POST /v1/accounts/me/identities`.

## Refresh

`POST /v1/auth/refresh {"refresh_token": "…"}` trả về một cặp token mới. Mỗi refresh token chỉ dùng được một lần. Dùng lại token cũ, hoặc hai lần refresh cùng một token, sẽ đăng xuất phiên. Vì vậy hãy refresh theo kiểu single flight, khi access token còn dưới một phút hoặc khi gặp 401 đầu tiên, và cho các request khác chờ. Ứng dụng lưu refresh token đã mã hóa bằng một khóa trong Keystore.

Khi gặp `session_revoked`, `session_expired` hoặc `invalid_refresh_token`, đưa người dùng về màn đăng nhập. `account_suspended` nghĩa là tài khoản đang bị tạm khóa.

## Xác thực lại

428 `reauth_required` nghĩa là lời gọi cần một lần đăng nhập trong 15 phút gần nhất. Gửi bằng chứng mới lên `POST /v1/auth/sessions/current/reauthenticate`, thay access token bằng token nó trả về, giữ nguyên refresh token, rồi gọi lại. Bằng chứng của một địa chỉ khác trả 403 `wrong_account`. Đừng bao giờ gọi sign-in cho việc này: địa chỉ chưa biết sẽ tạo ra một tài khoản mới.

## Đăng xuất và thiết bị

`DELETE /v1/auth/sessions/current` kết thúc phiên này; bỏ access token đi. `GET /v1/auth/sessions` liệt kê các thiết bị, `DELETE /v1/auth/sessions/{id}` đăng xuất một thiết bị, và `DELETE /v1/auth/sessions/others` đăng xuất các thiết bị còn lại sau một lần đăng nhập gần đây.
