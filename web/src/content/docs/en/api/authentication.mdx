A user signs in with a phone number, a Google account or an emailed code; the first sign-in creates the account. Staff sign in to the console with a session cookie instead; see [Console](/en/architecture/console).

## Sign in

Send one proof to `POST /v1/auth/sign-in` with an `Idempotency-Key` and an optional device name:

```json title="POST /v1/auth/sign-in"
{ "phone_token": "eyJhbGciOi...", "device_name": "Pixel 9" }
```

- `phone_token`: the token Firebase returns after an SMS code or SIM check. Sign out of Firebase once you have it.
- `google_token`: the ID token from Android Credential Manager.
- `email_code`: `{challenge_id, code}`. Get the challenge from `POST /v1/auth/email-codes {"email": "…"}` first.

The answer holds `access_token`, `access_token_expires_at`, `refresh_token` and `account`. `account.is_new` means this sign-in created the account, so ask for a profile.

| Answer | What to do |
|---|---|
| 401 `invalid_phone_token`, `invalid_google_token` | get a new token (tokens last 5 minutes) |
| 422 `invalid_phone` | the number is not a Vietnamese mobile |
| 422 `invalid_code` | let the person retype; `details.attempts_left` |
| 422 `code_expired`, `code_locked` | ask for a new code |
| 429 `otp_too_soon`, `otp_limit` | wait `details.retry_after` seconds |
| 503 `unavailable` | retry with the same token |

## Calling the API

```http
Authorization: Bearer <access_token>
```

The access token lasts 15 minutes. On a bearer call, 401 is always about the bearer (`unauthenticated`, `invalid_token`, `session_revoked`, `session_expired`); a bad proof on such a call is 422. 403 `phone_required` means the call needs a phone; add one with `POST /v1/accounts/me/identities`.

## Refresh

`POST /v1/auth/refresh {"refresh_token": "…"}` returns a new pair. A refresh token works once; reusing one, or two refreshes with one token, signs the session out. So refresh as a single flight, when less than a minute is left or on the first 401, and let other requests wait. The app keeps the refresh token encrypted under a Keystore key.

On `session_revoked`, `session_expired` or `invalid_refresh_token`, send the person to sign-in. `account_suspended` means the account is suspended.

## Reauthenticate

A 428 `reauth_required` means the call needs a sign-in within 15 minutes. Send a fresh proof to `POST /v1/auth/sessions/current/reauthenticate`, replace the access token with the one it returns, keep the refresh token, and repeat the call. A proof of another address is 403 `wrong_account`. Never call sign-in for this: an unknown address would create a new account.

## Sign out and devices

`DELETE /v1/auth/sessions/current` ends this session; discard the access token. `GET /v1/auth/sessions` lists devices, `DELETE /v1/auth/sessions/{id}` signs one out, and `DELETE /v1/auth/sessions/others` signs out the rest after a recent sign-in.
