The server refuses a question before its turn opens; the runtime ends a turn while it runs. A refusal of the first kind comes back at once as an HTTP error. An ending of the second kind reaches the console as `turn.finished`, with the turn's status and the stop reason.

## Before the turn opens

| Check | Result |
|---|---|
| The picked agent is unknown or not a console agent | 404 `ai_agent_not_found` |
| The picked agent is turned off | 409 `ai_agent_disabled` |
| The chat is unknown, or another member's own | 404 `agent_conversation_not_found` |
| Over 30 questions and steers in a minute from one member, counted by each server replica | 429 `agent_rate_limited` |
| The question is empty once cleaned | 422 `agent_input_rejected` |
| The question is over 8000 characters, or a steer over 4000 | 400 `invalid_request` |
| The chat has a turn running | 409 `agent_turn_in_progress` |
| The agent has no route in Bifrost, or the runtime refuses the run, is full or cannot be reached | 503 `agent_unavailable`; the new turn is deleted, and the rest of the console works on |

A rate limit refusal is recorded, and the AI settings count them. A spent budget is not checked here: the model call that finds it spent ends the turn, as below.

## While the turn runs

| Limit | Default | When reached |
|---|---|---|
| The turn's deadline, the agent's limit from 10 to 300 seconds | 60 seconds | The turn ends `timed_out`; the finished steps stay. <Req id="NFR-PERF-02" /> |
| A command's timeout | 120 seconds, unless the model sets one | The command is killed; the model reads what it printed and goes on. |
| The same commands giving the same results | 3 steps in a row | The turn ends with the stop reason `loop`. |
| The model's output token limit | the model's | The answer is cut; it is stored, and the stop reason is `length`. |
| The model's context window | the model's | The turn ends with `context_full`. The history is never trimmed, so the member starts a new chat. |
| A workspace's size | 1 GB | The workspace is not saved; the last saved one stays. |

A model call that gets a 429, a 5xx or a dropped connection is tried twice more, one and then two seconds later. A call that still fails ends the turn `failed`, after a `step.failed` event. There is no limit on the number of steps: the deadline and the loop check end a runaway turn.

## Budgets

Each agent has a monthly budget in USD, set on its page in the AI settings. Bifrost enforces it on the agent's team and resets it on the first of the month (UTC). A budget spent midway makes Bifrost answer 402; the runtime does not retry it, and the turn ends `failed` with the stop reason `budget`. The ask box then stays locked for that agent until the budget resets or an admin raises it; the rest of the console works on. <Req id="UC-MOD-08" />

## How a turn ends

The console shows a strip under a turn that did not simply answer, and offers **Resume** where going on can help.

| Status | Stop reason | The console says | Resume |
|---|---|---|---|
| `succeeded` | `done` | nothing: the answer is the ending | no |
| `succeeded` | `length` | the answer was cut short; ask for the rest | no |
| `succeeded` | `loop` | it went round in circles | no |
| `succeeded` | `context_full` | the chat is full; start a new one | no |
| `paused` | `paused` | paused, with the commands it ran | yes |
| `stopped` | `stopped` | stopped, with the commands it ran | yes |
| `timed_out` | `deadline` | past its time limit; what it found is kept | yes |
| `failed` | `budget` | the month's budget is spent | no |
| `failed` | none, with an error | it broke on the way, with the error | yes |

A turn fails with an error when a model call fails, the runtime's stream breaks or ends without a result, the server stops while it runs, or the server finds it still running a minute past its deadline. In each case the finished steps stay. Only the chat's latest turn can resume.

## Known limits

- The rate limit is counted in each server replica's memory, so with several replicas a member may send a little more.
- A command that already reached the server's API runs to its end there, even when the turn is stopped.
- A sandbox has no memory or CPU limit of its own in the cluster, only the runtime pod's ([The runtime and its sandbox](/en/agent/runtime#the-runtimes-pod)).
