The agent writes its answer as Markdown, and the console renders it. The server puts the console's conventions into every console agent's system prompt, after the agent's own instructions. They are the console's contract with the model, so an admin's instructions cannot drop them, and they read the same on every turn, which keeps them in the model's prompt cache.

## What an answer may hold

| In the answer | Written as | The console shows |
|---|---|---|
| Text and tables | Markdown | Rendered text and tables. |
| A record | `[its name](kind:id)`, the kind being `account`, `ticket`, `order`, `listing` or `report` | A chip that previews the record on hover and opens it on a click. |
| A diagram | a ` ```mermaid ` block | The diagram, drawn in the console's colours. |
| A chart | a ` ```vega-lite ` block of Vega-Lite JSON, data inline and no styling | The chart, styled by the console. |
| Quick replies | a ` ```options ` block at the end, one reply per line | A button per reply; the one picked comes back as the member's next message. |

A record of another kind, such as a feedback item, is named in words.

## Plain words

The console shows the member the commands the agent ran, so the answer need not. The conventions ask the model to say in plain words what it looked at or did, as a colleague would, without command names or ids.

## The work above the answer

While a turn runs, the console lists what the agent does: each command it ran, named by its operation's summary, and the text it wrote between them. Once the turn ends, the list folds into one line, such as "Worked for 38 s · 8 commands", and opens on a click. Before the first event arrives, the console shows one word that changes slowly, with a clock after three seconds.

A change the agent asked for shows as a card under the answer, with **Approve** and **Reject** ([Changes and approvals](/en/agent/approvals)). A turn that did not simply answer shows how it ended, and **Resume** when it can go on ([Limits and failures](/en/agent/limits#how-a-turn-ends)).

## What a member writes

- **`@` names a record.** Typing `@` opens a menu of tickets, accounts, orders, listings and report cases. The record goes into the question as `[Name](kind:id)`, the same form the agent writes, and shows as a chip.
- **`/` runs a page's command.** A page may offer commands in its ask box. A ticket's chat has `/reply`, which asks the agent for a reply and puts it in the ticket's reply box, and `/summary`, which asks for a handoff summary. A command only writes a question for the agent; it calls nothing by itself.
- **Starters.** A record's empty chat offers a few questions to start with.
- **The agent picker.** Beside send, a member picks which console agent answers ([Agents and settings](/en/agent/setup)).
