A console member opens an account, a ticket or a chat of their own and asks the agent a question in plain words. The agent works in a sandbox of its own. It reads and changes ShopNexus through the console's own API, with a command-line tool called `shopnexus`, as the member who asked. It answers in Markdown: text, tables, record chips, diagrams, charts and quick replies. <Req id="UC-MOD-08" />

The agent changes nothing on its own. Every change it asks for becomes an approval request in the chat. A member approves it, and only then does the request run, as that member, into the audit log under their name. <Req id="BR-MOD-03" /> An instruction hidden in a user's message can at worst make the agent ask for a wrong change, which a member then reads and rejects.

## The parts

The console calls only the server. The server opens a turn and hands it to the agent runtime, a service of its own on the internal network. The runtime calls the model through Bifrost with the agent's key, and runs the model's commands in a sandbox. A `shopnexus` command reaches the server's API through a socket the runtime serves, which adds the turn's token. Everything the runtime does streams back to the server, which stores it and sends it on to the console.

The runtime keeps nothing between turns but the conversation's workspace. The server owns the history and sends it whole with each turn. [The runtime and its sandbox](/en/agent/runtime) covers the inside.

## What a turn may call

A turn may call a console operation when two things hold:

- **The agent holds its capability.** Each console operation names one in the API spec, such as `tickets.read` or `accounts.suspend`. An admin picks an agent's capabilities in the AI settings.
- **The member may use it.** Every call runs as the member who asked, so their role and the handler's own checks apply. An admin's turn reads monitoring; a moderator's turn does not even see those commands.

[Commands and capabilities](/en/agent/tools) lists them and says how the server checks each call.

## The member's screen

A turn shows up as it happens. Above the answer the console lists the commands the agent ran, each named by what it does, and folds them into one line when the turn ends. A change the agent asks for shows as a card with **Approve** and **Reject**.

While the turn runs, the send button is **Pause** (Esc pauses too), and pressed again it is **Stop now**. Typing a line while it runs steers the agent. A paused, stopped or broken turn offers **Resume**. [Pause, stop, steer and resume](/en/agent/control) covers each.

## Chats

A chat holds questions and their answers, and it comes in two kinds.

- **Shared.** An account or a ticket has one chat, shared by every member who opens it, so the next shift sees what was asked. The first member to ask makes it. An account's report case and its feedback open the account's chat. Only an admin renames or deletes a shared chat (`403 agent_forbidden` otherwise).
- **Own.** A chat with no record belongs to the member who opened it, and nobody else sees it. An order's or a listing's **Ask the agent** opens a new one with the record already named. The member renames or deletes their own chats; an admin can too.

A chat with a turn running cannot be deleted (`409 agent_turn_in_progress`). A chat with no activity for 180 days is deleted with everything in it. <Req id="NFR-PRIV-02" />
