The server is the only place an agent's configuration lives. The agent keeps no copy: each segment gets it in the `agent_config` and `gateway` fields of `POST /runs`.

## Agents in `ai_agents`

The server's `ai_agents` table holds two kinds of agent, and the first rows come seeded.

| Kind | Seeded agents | Used by | Admins can |
|---|---|---|---|
| `console` | Console assistant (`console-agent`) | moderators, picked in the ask box | create, edit, turn on and off |
| `app` | Scam check, Listing photo reader, Search, Search embeddings | the server's code | change the model, limits and budget |

An agent has a display name ("Console assistant") and a slug (`console-agent`), which names its team in Bifrost. Each save of new instructions adds a version to `ai_agent_versions` with who saved it and when. A question that names no agent uses the Console assistant; an unknown agent or an `app` agent is 404 `ai_agent_not_found`, and one turned off is 409 `ai_agent_disabled`.

Admins manage agents under **Settings** in the console; [AI settings](/en/architecture/ai) covers the server's side. An agent's page holds its model (provider and model), its fallbacks, its monthly budget and its callers' rate limits; each model has a price. The Providers page is read-only, since a provider is an infra change. The server writes the teams, virtual keys, budgets and prices into Bifrost through its admin API ([Bifrost gateway](/en/operations/cluster/llm-gateway#keys-and-budgets)).

## Config per segment

```jsonc
"agent_config": {
  "id": "uuid", "name": "Console assistant",
  "instructions": "…", "instructions_version": 3,
  "tools": ["ticket_get", "account_get"],  // MCP tools the agent may use
  "limits": { "deadline_s": 60, "max_model_calls": 40, "context_window": 128000,
              "tool_timeout_s": 20, "tool_attempts": 3, "max_tokens": 4096 }
},
"gateway": {
  "key": "sk-bf-…",                         // the agent's Bifrost virtual key
  "model": "upstream/claude-sonnet-5-5",   // provider/model
  "fallbacks": [],                         // provider/model, tried in order
  "prices": { "upstream/claude-sonnet-5-5": { "input": 2e-6, "output": 1e-5, "cache_read": null, "cache_write": null } }
}
```

The agent drops unknown keys of `agent_config`; a value out of range refuses the whole request with 400. A segment without `gateway` is refused with 400 too. The agent never logs or stores the key, and prices each call with `prices` (USD per token; a null cache price is the input price). A segment's system prompt is the built-in prompt (role, the open record, the moderation and support rules), the output tool rules, the agent's `instructions` and the skill's prompt when the question uses one.

## Environment

Values that are the same in compose and every cluster stack live in one shared agent environment file, which both read. The two tokens are generated with the stack's other keys. The agent holds no model key of its own.

| Variable | Side | Meaning |
|---|---|---|
| `AGENT_BASE_URL` | server | The agent's internal address, such as `http://agent-dev:3000` |
| `AGENT_SERVICE_TOKEN` | both | Token the server sends with `POST /runs`; empty refuses every request |
| `AGENT_MCP_ADDR` | server | The MCP server's listener, `0.0.0.0:9090` |
| `AGENT_MCP_TOKEN` | both | Token the agent sends to MCP and the control endpoint |
| `MCP_SERVER_URL` | agent | The server's `/mcp`, such as `http://server-dev:9090/mcp`; its origin also serves the control endpoint |
| `GATEWAY_BASE_URL` | agent | Bifrost's OpenAI-compatible endpoint, `http://bifrost:8080/v1` |
| Bifrost's admin URL and login | server | For writing teams, keys and budgets, and for the Settings pages |
| `AGENT_TURN_DEADLINE_MS` | agent | A segment's default deadline, 60 000 |
| `FEATURE_ALL_AGENT`, `FEATURE_LLM` | agent | `false` refuses every segment with 503 |

Each token has at least 32 characters; the server's environment generator writes both as 32 random bytes. No log line carries a token, a gateway key or the admin password. The agent repository's example environment lists the rest, all optional.

## A local run

The agent has no compose file of its own. It runs on the stack's Bifrost and MCP, from the umbrella repo's `docker-compose.yml` or the cluster.

```bash
cd agent
npm install
cp .env.example .env
# Set AGENT_SERVICE_TOKEN, AGENT_MCP_TOKEN, MCP_SERVER_URL, GATEWAY_BASE_URL and CLI_GATEWAY_KEY to the stack's.
npm run start:dev
npm run chat -- "Có bao nhiêu ticket đang mở?"
```

`npm run chat` posts one `new` segment to the agent on `PORT` as `CLI_MEMBER_ID`, with `CLI_GATEWAY_KEY` and `CLI_GATEWAY_MODEL` as its `gateway` at zero prices, and prints its events and end line. Take the key from the `console-agent` team in Bifrost's UI. It calls the real model and MCP, which may cost money. Without the server's control endpoint the polls fail and the segment goes on without Pause, Stop now or updates.
