The server is the only place an agent's settings live. The runtime keeps no copy: each turn gets the system prompt, the model and the key from the server, and the turn's token carries the capabilities. Admins manage agents under **Settings** in the console. <Req id="UC-MOD-12" /> <Req id="FR-MOD-06" />

## Two kinds of agent

| Kind | Seeded agents | Used by | Admins can |
|---|---|---|---|
| Console | Console assistant (`console-agent`) | console members, picked in the ask box | create, edit, turn on and off |
| App | Scam check, Listing photo reader, Search, Search embeddings | the server's own code | change the model, fallbacks, limits, budget and callers |

An agent has a display name ("Console assistant") and a slug (`console-agent`), which names its team and its caller in Bifrost. A question that names no agent uses the Console assistant. The ask box's picker lists the console agents that are turned on, each with its icon and purpose. [AI settings](/en/architecture/ai) covers the app agents.

## A console agent's settings

| Setting | What it does |
|---|---|
| Model | The provider and model a turn calls. It needs a price, or the save is refused with `ai_model_unpriced`. |
| Fallbacks | Models the app agents fall back to. A console turn calls the agent's model alone. |
| Instructions | The first part of the system prompt. Each save makes a version, with who saved it and when, and old versions stay readable. |
| Capabilities | The operations a turn may call ([Commands and capabilities](/en/agent/tools#capabilities)). A capability the API spec does not name is refused with `ai_agent_invalid`. |
| Deadline | How long a turn may run: 10 to 300 seconds, 60 by default. |
| Monthly budget | USD a month, enforced by Bifrost on the agent's team. |
| Callers' rate limits | Requests a minute for the agent's caller in Bifrost. |
| On or off | A turned-off agent takes no question (`409 ai_agent_disabled`). |

Every change is checked and stored with an entry in the audit log in one transaction. A save that races another save of the same agent is refused with `try_again`, so neither overwrites the other unseen. The server then writes the agent's team, budget, virtual key and prices into Bifrost ([Bifrost gateway](/en/operations/cluster/llm-gateway#keys-and-budgets)); when Bifrost does not answer, the change stays saved and the next sync, every 5 minutes, applies it.

## What a turn takes

When a turn starts, the server reads the agent and takes:

- **The route**: the agent's model and its virtual key, from the keys the server holds for Bifrost. An agent with no key yet answers `503 agent_unavailable`.
- **The system prompt**: the agent's instructions, the console's conventions and the commands its capabilities and the member's role grant.
- **The capabilities and the member's role**, copied onto the turn. A change to the agent's capabilities reaches turns that start or resume after it, not a turn already running. The role leaves admin-only commands out of a moderator's turn ([Roles](/en/agent/tools#roles)).
- **The deadline** from the agent's limits.

The seeded Console assistant reads only: it holds `tickets.read`, `accounts.read`, `reports.read`, `orders.read`, `listings.read`, `feedback.read`, `audit.read` and `monitoring.read`. An admin who wants it to ask for changes grants the capabilities that change things, such as `tickets.reply` or `accounts.suspend`; each change still waits for an approval.

## Activity

The agent's page and the AI settings' overview show what the console agents did over a range of days: <Req id="UC-MOD-12" />

- the spend per day and per agent, against each budget, read from Bifrost's logs;
- each agent's API calls per operation: the count, the changes held for approval, the errors, the average time and the last call;
- the turns by how they ended, such as `succeeded`, `timed_out` or stopped for `loop` or `budget`;
- the approvals by status, and the rate limit refusals.

## Where it runs

The runtime runs next to the server, Bifrost and a package proxy: in both Compose stacks from the root `docker-compose.yml`, and in the cluster in each stack whose chart values turn it on, which is the dev stack. Only the server and the agent call Bifrost, and only the server calls the runtime. The pages that cover it:

- [Bifrost gateway](/en/operations/cluster/llm-gateway) for keys, budgets, prices and spend.
